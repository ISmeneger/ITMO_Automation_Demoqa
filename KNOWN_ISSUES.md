# Известные дефекты и изменения DemoQA

Состояние на **13 октября 2026 года**. Полный локальный прогон: **60 passed, 2 xfailed**, без failed/errors. Проверки функционального результата, дефектов и ограничений перечислены отдельно ниже.

## 1. Close не закрывает окно Practice Form

**Шаги:** открыть Practice Form, заполнить обязательные поля, отправить форму и нажать Close в окне результата.

**Ожидается:** окно закрывается.

**Наблюдается:** окно остаётся видимым. Поведение подтверждено в локальном прогоне.

**Тест:** `tests/test_form_modal_close.py::test_close_submitted_form`.

Strict xfail применяется к AssertionError при оставшемся видимым окне после клика. Открытие формы, поиск кнопки и ошибки браузера не маскируются. Если окно корректно закроется, будет strict XPASS.

**Возможная причина:** опубликованный JS вызывает `ReactDOM.findDOMNode` перед закрытием окна. Предположение о несовместимости требует подтверждения JavaScript stack trace.

## 2. Удалённая запись восстанавливается при следующем удалении

**Шаги:** открыть Web Tables с исходными тремя записями, удалить первую запись, дождаться её исчезновения и удалить следующую.

**Ожидается:** обе удалённые записи отсутствуют, остаётся одна исходная запись.

**Наблюдается:** ранее удалённая запись появляется снова. Специальный тест подтвердил это условие через XFAIL в локальном прогоне.

**Тест:** `tests/test_webtables.py::test_tables`.

Тест выбирает запись по имени, ждёт исчезновения именно выбранной записи и проверяет пересечение текущих имён с уже удалёнными. Strict xfail разрешён только для `RestoredDeletedRecordError`. Таймауты, неверное начальное состояние и остальные assertions остаются падениями. Если все три записи удалятся корректно, будет strict XPASS.

**Возможная причина:** обработчики ячеек созданы внутри `useMemo(..., [])`, а удаление фильтрует первоначальный массив записей. Это указывает на устаревшее состояние в замыкании.

## 3. Footer перекрывает нижние кнопки

В промежуточном локальном прогоне footer перехватывал клики Submit и Next. Метод click сначала выполняет обычный клик. Только при ElementClickInterceptedException с явно указанным footer для button/a используется клавиатурная активация Enter. Footer не скрывается; другие перекрытия остаются ошибками.

Это позволяет проверять функциональный результат через клавиатуру, но не подтверждает доступность перекрытых кнопок мышью.

## Изменения покрытия относительно учебной версии

- Текущая Web Tables использует нативный table и не содержит обработчиков сортировки заголовков. Старый пример сохранён в `examples/webtables_sort_legacy.py` и не входит в UI-набор. Добавлены шесть проверок поддерживаемого поиска по данным столбцов.
- Размер страницы начинается с 10; выбора 5 больше нет. Проверка пагинации создаёт 8 записей в дополнение к исходным 3 и проверяет переходы между двумя страницами по реальным данным.
